# 2FA 成功後仍停留驗證頁的修正（2026-10-24）

應用版本 `3b640fcb450e45561c568b677e82daeae4f280ad` 已於 **2026-10-24 20:50 台灣時間**同步至 https://rangerbook-test.warmycat.com/login/ 。PR #176 維持 Draft；正式網站與認證服務未切換。後續文件提交不改變此部署版本。

## 原因與修正

唯讀檢查確認回報的測試帳號有成功的 `factor_verified` 稽核事件，同時有 `must_change_password=1`。既有 `state()` 將所有尚未取得完整權限的情況一律以「有綁定 TOTP」推斷 `mfa_required`，因此即使新 Session 已通過因素驗證，只要仍須更改臨時密碼，畫面就會再次顯示 2FA。側欄的登出選項也適用未完成登入，不能單憑此選項判斷已完整登入。

- `membership/service.py` 依實際剩餘限制回傳 MFA、初始設定或必要改密碼狀態；因素已驗證但須改密碼時，`logged_in=false`、`mfa_required=false`、`must_change_password=true`。無 2FA 但須改密碼的初次回應也維持受限狀態。
- `assets/js/member-page.js` 在必要改密碼階段只顯示密碼表單與「請先變更密碼以完成登入」，隱藏不適用的重新驗證／Google／2FA 管理卡片。尚未通過 MFA 的人直接存取設定頁會返回登入流程。
- 必要改密碼成功且重新取得後端完整登入狀態後，導向首頁；一般沒有此限制的 2FA 登入直接回首頁，側欄顯示個人功能。
- `assets/locales/sitewide-overrides.json` 同步繁中、英文、日文及泰文；`sw.js` 更新 app hash `69fa33cd7362`，資料 hash `4a32f0c67d14` 不變，私人內容仍不快取。

沒有變更 `full()` 權限依賴、MFA 防重放、目前密碼驗證或密碼變更後的 Session 撤銷。沒有直接清除帳號的強制改密碼欄位，沒有操作真人帳號的密碼、Google、TOTP 或恢復碼。

## 同步與回復

使用固定公開 commit 並比對來源／隔離檔案 SHA-256；停止服務前先以 `asm-exec` 子程序確認動態機密解析及環境／金鑰有效。先備份 SQLite、設定、入口憑證與私人隊伍，再同步會員設定頁腳本、詞庫及隔離 `membership/service.py`，保留原前端並僅重啟隔離 auth。測試站另外保留既有 stage-bootstrap，正式站不採用此隔離入口。

受限操作與備份目錄為 `/home/ubuntu/rangerbook-member-login-completion-20261024-3b640fcb/`；`backup/` 含資料及原後端備份，`previous-site/` 為舊前端，`result.json` 記錄實際 HTTPS 結果與保留檢查。失敗時回復前端及後端程式，再檢查測試 auth，**不自動還原資料庫**。本次沒有 schema migration、寄信、增加額度、調整 IAM 或 Nginx；正式發布仍待站長核准。

實際同步更新三個公開檔案（含原 stage-bootstrap）與一個隔離後端檔案。身份／角色／綁定／恢復碼、私人隊伍、金鑰／入口及 runtime 設定摘要一致，SQLite integrity=ok，郵件預算仍4/5。正式 auth、Nginx 與機密 provider 程序維持，正式網站及 auth health 200。未使用真人因素；原生瀏覽器登入與實機仍由站長回測。
