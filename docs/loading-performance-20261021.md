# 載入流程檢查與改善

## 確認的問題

1. `pwa-data.js` 與 Service Worker 都強制 `no-store`。即使同一版本資料已快取，Service Worker 仍先等待網路，最久 10 秒才讀取快取；換頁後大型 JSON 又重新下載。
2. V2 載入器先等語系檔，再下載資料；角色與能力資料也有序列等待。角色列表及單一詳細頁都需要完整 6.74 MB 官方四語系檔與 5.88 MB 全角色資料。
3. 詳細頁會等第三方動畫索引及 metadata，才第一次顯示角色數值。動畫補充功能還會讀取整份投射物資料。
4. 舊角色補充模組重複要求全角色資料，且每次重新做相同的轉換。

## 修正後的流程

| 畫面／機制 | 新流程 |
| --- | --- |
| 角色列表 | 先用小型清單顯示 60 張卡片、名稱／星數／基本數值及一般篩選；背景補齊完整進階篩選，保留使用者已選條件。完整資料暫時失敗仍保留列表。 |
| 單一詳細頁 | 僅讀取該角色的資料包，包含完整原始數值、技能、能力、才能、進化關聯、對應四語詞條與單一角色投射物。共 2,306 包，最大 25,352 bytes；兔兔範例為 13,182 bytes。 |
| 動畫 | 角色內容先顯示，前搖時間收到後才補上，動畫主機不阻塞數值。動畫使用同一資料包中的投射物。 |
| 全站語系 | 一般資料頁僅下載中文基準、英文後備與目前語言；角色名稱保留四語別名，跨語搜尋不受影響。角色頁則只需目前畫面相關的名稱／詞條。 |
| 全站快取 | 先驗證已儲存的同版本內容並立即回傳。網路 URL 帶內容雜湊以重用 HTTP 快取，資料變動才換 URL；重複及同時請求合併。保留雜湊驗證、私人 API 排除、快取容量與更新同意機制。 |

快速資料在 `scripts/build-pwa.mjs` 打包時由正式 V2 資料重新產生，並同時納入發行雜湊與離線清單。毋須修改正式後端或手動維護第二份資料。產物位於 `res/v2/fast/`，不提交至原始碼；每次資料更新的 Pages 打包皆重新產生。

## 比較量測

本機 Chromium、英文、250 KB/s JSON 模擬傳輸速率、每筆 JSON 額外 75 ms、動畫索引延遲 2 秒；HTTP 快取及 Service Worker 在比較測試中停用，圖片／其他遠端服務亦排除。測量從導航到卡片／等級控制可見，並非網頁全部資源下載完成。前後使用同一份正式資料與相同環境，結果不代表使用者實際網路的保證時間。

| 畫面 | 修正前 | 修正後 | 減少 |
| --- | ---: | ---: | ---: |
| 角色列表首次顯示 | 8.31 秒 | 2.01 秒 | 76% |
| 從列表進入詳細頁 | 9.91 秒 | 1.71 秒 | 83% |
| 再開同一詳細頁 | 7.64 秒 | 1.65 秒 | 78% |

列表的完整進階篩選仍會在背景下載全角色資料；首次快速顯示不表示背景資料已全部下載。後續可用快取直接讀取。第三方圖片與動畫載入速度仍取決於其主機。

## 驗證

- 逐筆比較全部 2,306 個角色資料包與正式原始角色，保留每一欄；檢查清單數值、進化目標、四語名稱別名與語系欄位。
- 四語瀏覽器測試：完整角色／能力／官方語系／投射物資料刻意回傳失敗，動畫索引刻意延遲 5 秒；詳細頁仍先顯示，且沒有請求這些完整資料。清單在完整資料失敗時仍顯示 60 張卡片。
- Service Worker 暖快取測試：已驗證資料再次讀取時網路請求數不增加；版本不符、損壞快取與私人資料維持原有檢查。
- 真實 Chromium PWA：根路徑及 `/rangerbook/`、離線／恢復、深層網址、版本更新、跨分頁同意、四語及深淺主題。
- 原有四語翻譯、角色篩選／等級、PvP 隊伍、October 13 介面與 18 項 V2 資料介面測試。
